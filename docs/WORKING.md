# Working notes

This is the shared record for the current project. Update it when the team confirms a decision or hands off work. Link to the relevant source, issue or commit so a teammate can resume without chat history.

## Opening checklist

1. Check in on-site and confirm the team roster in Sprintd. Rank the partner challenges together and capture the assignment after the 10:15 announcement.
2. Open the assigned brief and template. During the workshop, confirm the core AI task, deliverable, judging criteria, data permissions and any challenge-specific model or tooling constraints.
3. Agree on one demo workflow and how to verify it. Confirm the build repository and move these working notes there if the team starts from a new template repository. Link the build repository here so contributors know where to work.
4. Assign owners for the core workflow, integration/demo and submission artifacts. One person can cover several areas. Smoke-test actual Apertus access and integrations early.

## Decisions and handoff

For a decision, capture the date, choice, reason and source. Keep a linked model inventory that captures name, version and role across development, runtime and evaluation once the team starts using models.

For a handoff, include the owner, branch or commit, what works, how to run the relevant check and the next unresolved item. Use short-lived branches where they help teammates avoid collisions. Coordinate shared contracts and files before parallel changes, and integrate the demo path early enough to try it from a clean checkout.

As the prototype takes shape, record one representative case and one meaningful failure case. Keep the exact commands, inputs and measured results close to the code so they can support the report and pitch.
